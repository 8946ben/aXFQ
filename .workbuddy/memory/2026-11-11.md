## 第二轮：设置页去掉默认时长 + 修「拖动表盘改写预设」bug

- **设置页删掉「默认时长」三个输入框**（专注/短休/长休）：只剩一张卡片「完成后的行为」，放两个复选框（自动开始下一段 / 完成提示音）。`panel.html` 的 `.durations` 块、`panel.js` 的 `syncSettings()` 三行赋值和 `dur-*` 的 change 监听循环、`panel.css` 的 `.durations` 规则全部删除，`grep dur-focus` 确认无残留。
- **bug 根因**：`main.js` 的 `timer:set-duration` 里 `if (p) p.minutes = m` —— 拖动表盘松手会把**预设标签的 minutes 直接改掉**，所以设置里配好的时长被悄悄覆盖。
- **修法**：预设模式下拖动只改 `timer.total/remaining`（本次计时），**不回写** `state.presets`，也不 `saveState()`/广播；内置模式（focus/short/long）仍写回 `state.pomodoro[mode]`（现在没有输入框了，拖动是唯一调法，需要记忆性）。
- **配套两处**：① 拖动结束的 toast 在预设模式下改成「本次 X 分钟 · 不改动标签设置」，让用户知道没被覆盖；② 设置页「我的标签」提示补一句「拖动表盘只调整本次计时，不会改动这里配好的时长」。
- 语义定案：**自定义标签的 minutes 是模板**（只有标签编辑器能改，点标签 = 套用模板），**拖动表盘是本次临时调整**，重置(`setMode`)或重点一次标签就回到模板值。`finishTimer()` 用的是 `timer.total` 算分钟数，所以临时调整后统计也准（已核对，无需改）。
- CDP 验证：设置页 0 个 `input[type=number]`、2 个复选框；预设 50 → 拖到 65（`timer.total=65`，`preset.minutes` 仍 50）→ 重点标签回到 50；内置专注拖到 35 后切走再回来仍是 35；标签编辑器 `pe-minutes` 与表情网格正常。预览图重做。

## 打包版内存实测（09:5x）

用 CDP（`--remote-debugging-port=9333`）操作 + PowerShell 采 `PrivateMemorySize64`，测 `dist/win-unpacked` 的打包版：

| 状态 | 进程 | 工作集 | 私有提交 |
| --- | --- | --- | --- |
| 冷启动（面板隐藏） | 5 | ~452 MB | ~225 MB |
| 打开面板·番茄钟 | 5 | 468 MB | 239 MB |
| 便签 / 最近访问 / 统计 / 设置 | 5 | 481–498 MB | 235–255 MB |
| 计时运行 90s | 5 | 528–536 MB | 275–283 MB |
| 重置后 | 5 | 539 MB | 287 MB（Chromium 不归还，正常） |

- 进程明细（面板开 + 计时）：gpu-process 私有 122 MB / 工作集 155 MB；panel renderer 55 MB / 116 MB；ball renderer 44 MB / 96 MB；main 39 MB / 108 MB（工作集大头是映射的 Electron DLL）；utility 12 MB。
- **无泄漏**：空转 60s 225→221 平稳；计时中 90s 稳定在 282±3；`performance.memory` JS 堆只有 10 MB，内存全在引擎基线。
- **闲置 CPU 近零**：10 秒累计 0.17 CPU 秒（约 0.07% 单核），透明置顶窗口没有持续重绘 —— 和 clawd 的 gpu-process 恶意增长（涨到 5.4 GB）完全不同性质。
- 横向参考：同机 VS Code 9 进程 1050 MB、另一个 electron 应用 9 进程 676 MB。
- 省内存的可选手段（未做）：panel 关闭时 destroy 而非 hide（省约 45–55 MB，代价是重开有 150–300ms 延迟）；`webPreferences.spellcheck:false`。**不要**禁硬件加速——透明窗口会转软件合成，CPU 反而涨。
- 结论：作为 Electron 应用 270–290 MB 私有提交属正常偏低水位，可交付。

### 口径澄清（09:55 补测）

同一时刻三种口径，5 进程合计：**工作集 450.3 MB / 专用工作集 145.0 MB / 私有提交 221.8 MB**。

- 450 − 305（共享 Chromium DLL，5 个进程各算一遍）= 145 → 任务管理器「内存」列显示的就是这个专用工作集。
- 145 + 77（已换出 pagefile）= 222 → 「提交大小」列，需手动加列。
- 单进程例子：gpu-process 工作集 124.3 / 专用工作集 63.4 / 私有提交 102.6，三个数方向完全不同。
- **对外报占用优先说「私有提交」或「专用工作集」**，`WorkingSet64` 含共享、多进程相加会虚高 3 倍。上一轮报的 450 MB 就是这个坑，实际常驻仅约 145 MB，面板+计时约 190 MB。
- `虚拟大小` 单进程 2–3.5 GB 是 Chromium 保留的地址空间（V8 cage/沙箱），不是真实占用，别当内存看。
